# 47. FP16 (Half Precision)

**Stage:** 2 / 7 | **Priority:** Must know | **Prerequisites:** [BF16](46_BF16.md)

## In one sentence
FP16 is a 16-bit float with 5 exponent and 10 mantissa bits — more precise than BF16 but with a much narrower range (max ≈ 65,504).

## Plain-English explanation
FP16 and BF16 both use 2 bytes and run at the same Tensor Core speed on the A100. The trade-off:
- FP16: finer detail, but numbers above ~65k overflow to infinity and tiny numbers underflow.
- BF16: coarser detail, but huge range.
LLMs trained in BF16 can have activations that overflow in FP16, producing NaNs or garbage.

## Technical depth
- Layout 1/5/10; range ~6e-8 (subnormal) to 65,504.
- A100 FP16 Tensor Core peak: ~312 TFLOPS dense (same as BF16).
- Some quantized kernels historically required FP16 activations (e.g., older AWQ/GPTQ kernels); newer ones support BF16 too. W4A16 "A16" can mean either.
- If a model was trained in BF16, running FP16 can subtly change outputs even without overflow.

## Backend-engineer analogy
Two 16-bit encodings with different trade-offs — like choosing a fixed-point format with more decimals but a smaller max value.

## Why it matters for GreenMind
Usually no speed advantage over BF16 on A100, but some quantization kernels may run in FP16 activation mode. Check accuracy whenever activation dtype changes.

## Common mistakes
- Switching dtype to FP16 "for speed" — no gain on A100, possible quality risk.
